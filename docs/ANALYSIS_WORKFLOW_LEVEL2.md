# 二级算法 (Level 2)：多帧采样与平均化深度分析报告

## 1. 背景与核心定义
在视觉测量领域，单帧图像往往受制于传感器噪声、光照波动以及标定参数的微小抖动。
**二级算法 (Level 2)** 并非单帧图像处理的替代品，而是作为一种**时域滤波 (Temporal Filtering)** 阶段，在单帧算法（V1 或 V2）输出结果后实施，通过多帧数据聚合来提高最终输出的置信度。

---

## 2. 算法原理与正确性分析

### 2.1 统计聚合逻辑
1.  **结果缓冲**：系统维护一个长度为 $N$ (建议 $5 < N < 15$) 的滑动窗口或循环队列，存储最近有效的测量数据 $R = \{ (D_1, L_1), (D_2, L_2), \dots, (D_n, L_n) \}$。
2.  **去噪处理**：
    - **中值滤波 (Median Filter)**：首先剔除队列中因瞬间遮挡或算法误算产生的离群点（Outliers）。
    - **均值平滑 (Mean Averaging)**：对剩余的稳定数据求算术平均。
3.  **最终输出**：当且仅当队列填满且标准差 $\sigma$ 小于预设阈值时，向 UI 锁死最终分级结果。

### 2.2 正确性论证
- **噪声抵消**：根据大数定律，随机误差（如亚像素偏移、感光噪声）在多次测量后的均值会趋向于真实物理值。
- **治理抖动**：对于 **V2 (3D 位姿)** 方案中极度敏感的 `solvePnP` 输出，二级算法是其平滑化的必由之路。

---

## 3. 工作流互补性 (Complementarity)
二级算法在工作流中扮演“定海神针”的角色：
- **第一级 (Level 1)**：实时检测（V1 快速映射或 V2 3D 计算），负责提供原始采样。
- **第二级 (Level 2)**：状态锁定。当算法检测到芦笋连续在视野中稳定 500ms 以上时，自动切换至二级阶段进行高精度多次采样。

---

## 4. 风险与代价评估

### 4.1 核心挑战
- **响应延迟 (Latency)**：这是二级算法最大的负面效应。若采样 15 帧，在 30fps 下需要 500ms。对于追求“闪测”的用户，这可能显得程序响应迟钝。
- **运动模糊与偏移**：若用户在采样过程中移动了手机，二级算法会将不同视角的测量值混合，导致结果由于“平滑”而变得更加不准。
- **内存消耗**：需要额外的缓冲区和统计计算开销，但在现代移动设备上此项基本可忽略。

### 4.2 实施成本
- **UI 交互改进**：必须为用户提供明确的反馈（例如“正在采样...”进度条或锁定图标），否则用户会在结果跳动完成前移走手机。
- **传感器协同**：建议结合手机的 **陀螺仪 (Gyroscope)** 数据。若检测到较大抖动，则自动清空二级缓存并重置采样，以确数据的有效性。

---

## 5. 思考逻辑与论证过程
1.  **观察**：用户反馈单帧结果偶尔会跳变（例如从 A 级跳到 B 级再跳回 A 级）。
2.  **溯源**：这是由于 ArUco 标记检测在像素级别的亚像素抖动（Sub-pixel jitter）引起的。
3.  **解决**：这种物理级别的抖动无法通过优化单帧算法完全消除，只能通过时间轴上的滤波器治理。
4.  **结论**：二级算法是提升“商用稳定性”的最低成本手段。

---

## 6. 实施建议 (Implementation Strategy)

> [!TIP]
> **黄金组合**：V2 (纠正几何失真) + Level 2 (平滑检测噪声) = 工业级测量精度。

**建议参数**：
- **采样深度**：10 帧。
- **锁定条件**：ArUco 标记 100% 存在且其位姿变化率 $< 5\%$。
- **交互方案**：在 UI 上实时显示单帧值，但在结果稳定后用绿色高亮显示锁定后的均值。
